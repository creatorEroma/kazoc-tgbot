# Вселенные Наргуль и Ернура

Приватное веб-приложение ровно для двух человек: **Наргуль (nako)** и **Ернур (eroma)**.
Оба — администраторы с равными правами на всё общее.

Стек: Next.js (App Router) + TypeScript + Tailwind + Framer Motion, Supabase
(PostgreSQL, Auth, Storage, Realtime), хостинг Vercel.

---

## Запуск с нуля

### 1. Создать проект Supabase

1. [supabase.com](https://supabase.com) → **New project**. Регион — ближе к вам
   (например, Frankfurt). Пароль базы сохраните.
2. **Project Settings → API**: скопируйте `Project URL` и ключ `anon public`.

### 2. Применить схему базы

В **SQL Editor** выполните по очереди:

1. `supabase/migrations/0001_schema.sql` — таблицы, связи, индексы, триггеры, RLS.
2. `supabase/migrations/0002_storage.sql` — бакеты `media`, `voice`, `avatars` и политики.

### 3. Создать два аккаунта

1. **Authentication → Users → Add user** — создайте двух пользователей с почтой и
   паролем, включив «Auto Confirm User».
2. Скопируйте их `User UID`.
3. Откройте `supabase/seed.sql`, подставьте UUID вместо заглушек и выполните файл.
   Проверка в конце файла должна вернуть ровно две строки.

Больше двух профилей база не примет — на вставку третьего стоит защита.

### 4. Поднять лимит на размер файла

**Storage → Settings → Upload file size limit**. На бесплатном тарифе потолок
50 МБ, на Pro — до 50 ГБ. Бакеты своего лимита не имеют, ограничение только
на уровне проекта.

### 5. Локальный запуск

```bash
cd universes
cp .env.example .env.local     # подставьте свои URL, ключ и две почты
npm install
npm run dev                    # http://localhost:3000
```

### 6. Деплой на Vercel

1. **Add New → Project**, выберите этот репозиторий.
2. **Root Directory** → `universes` (важно: в корне репозитория лежит
   Telegram-бот на Python, у него свой деплой).
3. Переменные окружения: `NEXT_PUBLIC_SUPABASE_URL`,
   `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_ALLOWED_EMAILS`.
4. **Deploy**. После деплоя добавьте домен Vercel в
   **Supabase → Authentication → URL Configuration → Site URL**.

## Как устроена безопасность

- **Middleware** (`src/middleware.ts`) закрывает все маршруты, кроме `/vhod`.
- **RLS включён на всех таблицах.** Ключевой предикат — функция `is_member()`:
  доступ есть только у тех, чей `auth.uid()` лежит в `profiles`. Даже с валидным
  токеном постороннего база не отдаст ни строки.
- **Storage приватный.** Файлы отдаются только по подписанным ссылкам с часовым
  сроком жизни (`src/lib/media.ts`).
- **Личное и общее.** `scope = 'personal'` виден только владельцу, `scope =
  'shared'` — обоим. Это политики базы, а не логика интерфейса.

## Правило 30 минут

Продублировано в трёх местах, чтобы его нельзя было обойти:

1. Кнопка «Изменить» в интерфейсе исчезает сама через 30 минут — таймер тикает
   каждые 15 секунд, перезагрузка не нужна.
2. Триггер `enforce_message_rules` отклоняет `UPDATE` текста после окна и
   проставляет `edited_at`.
3. Тот же триггер запрещает менять автора и время, удалять чужое и ставить
   отметку о прочтении самому себе.

## Тяжёлые файлы

`src/lib/upload.ts` грузит файлы напрямую в Supabase Storage по протоколу TUS
кусками по 6 МБ. Это даёт три вещи: вес не упирается в лимиты серверных функций
Next.js, обрыв связи не убивает загрузку (докачка с последнего куска), и
прогресс считается в реальных байтах. Метаданные — размеры, длительность и
кадр-постер для видео — снимаются в браузере (`src/lib/mediaMeta.ts`), поэтому
превью в ленте появляется мгновенно.
